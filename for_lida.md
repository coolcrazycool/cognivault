# CogniVault: запуск через Docker с GigaChat и обычной папкой

Привет, Лида! Эта инструкция проведёт тебя от пустого сервера до рабочего поиска по твоим заметкам.

Что в итоге получится: поднимаешь CogniVault в Docker, эмбеддинги считает GigaChat (подключение по сертификату), а вместо Obsidian — простая папка. Кладёшь туда файлы, правишь их как обычно, а сервис сам их подхватывает и делает по ним умный поиск. Никакого Obsidian, никаких аккаунтов.

Вся работа — минут на двадцать. Команды можно копировать как есть.

---

## Что понадобится заранее

- **Docker и Docker Compose.** Проверь, что стоят: `docker --version` и `docker compose version` должны что-то ответить.
- **Сертификат GigaChat** — два файла: сам сертификат и закрытый ключ (обычно `client.pem` и `client.key`, могут называться иначе). Их выдают вместе с доступом к GigaChat.
- **Папка с заметками** — или уже готовая, или пустая, которую заведём по ходу.

---

## Шаг 1. Забрать код

Клонируем репозиторий и переключаемся на нужную ветку (поддержка GigaChat и папок живёт именно в ней):

```bash
git clone https://github.com/coolcrazycool/cognivault.git
cd cognivault
git checkout feat/gigachat-integration
```

Дальше все команды выполняй из этой папки (`cognivault`).

---

## Шаг 2. Положить сертификаты

Создай папку `certs` и скопируй туда свои файлы:

```bash
mkdir -p certs
cp /путь/до/твоего/client.pem certs/client.pem
cp /путь/до/твоего/client.key certs/client.key
```

Если вместе с сертификатом дали ещё и файл удостоверяющего центра (CA, корневой сертификат) — положи и его, например в `certs/ca.pem`. Он может понадобиться, чтобы сервер GigaChat признавался доверенным.

---

## Шаг 3. Завести папку для заметок

Можешь использовать любую существующую папку. Если начинаешь с нуля — создай рядом:

```bash
mkdir -p notes
```

Сюда ты будешь складывать файлы: `.md`, `.pdf`, `.csv`, картинки, Obsidian-канвасы. Внутри контейнера эта папка будет видна как `/vault` — это пригодится на шаге 7.

---

## Шаг 4. Настроить подключение

Создай в корне проекта файл `docker-compose.override.yml`. Docker Compose сам подхватит его и дополнит основную конфигурацию — основные файлы трогать не нужно.

Вот содержимое (поправь два места, отмечены комментариями):

```yaml
services:
  cognivault:
    environment:
      - EMBEDDING_PROVIDER=gigachat
      - EMBEDDING_DIMENSIONS=2560          # размерность EmbeddingsGigaR (менять не нужно)
      - GIGACHAT_BASE_URL=https://gigachat-ift.sberdevices.delta.sbrf.ru/v1
      - GIGACHAT_MODEL=EmbeddingsGigaR
      - GIGACHAT_CERT_PATH=/certs/client.pem
      - GIGACHAT_KEY_PATH=/certs/client.key
      # - GIGACHAT_CA_PATH=/certs/ca.pem   # <-- раскомментируй, если есть файл CA
      # - GIGACHAT_VERIFY_SSL=false        # см. раздел про проблемы — временный костыль
    volumes:
      - ./notes:/vault:ro                  # <-- слева твоя папка, если она называется не notes
      - ./certs:/certs:ro
```

Про `EMBEDDING_DIMENSIONS`. Это длина вектора модели EmbeddingsGigaR — она равна 2560, в файле уже проставлена, трогать не нужно. Важно понимать одно: Qdrant (база, где лежат эмбеддинги) запоминает это число при первом запуске. Если когда-нибудь придётся его поменять, базу нужно пересоздать заново: останови всё, удали том Qdrant (`docker compose down`, затем `docker volume rm cognivault_qdrant_data`) и запусти снова.

Папку монтируем «только на чтение» (`:ro`) — сервис в неё ничего не пишет, только читает. Твои файлы в безопасности.

---

## Шаг 5. Запустить

Поднимаем сам сервис и базу Qdrant:

```bash
docker compose up -d --build cognivault qdrant
```

Первый запуск дольше — Docker собирает образ. Дальше будет быстро.

В проекте есть ещё Prometheus и Grafana для графиков, но для работы они не нужны. Захочешь — запустишь потом просто `docker compose up -d`.

---

## Шаг 6. Проверить, что сервис живой

```bash
curl http://localhost:3030/health
```

Если в ответ пришло что-то вроде `{"status":"ok"}` — всё поднялось. Если соединение не открывается, дай контейнеру секунд десять и загляни в логи:

```bash
docker compose logs -f cognivault
```

В логах сразу будет видно, если GigaChat не принял сертификат или размерность не сошлась.

---

## Шаг 7. Завести пользователя

Доступ к API защищён ключом, поэтому сначала создадим пользователя. Он привязан к твоей папке:

```bash
docker compose exec cognivault \
  node dist/cli/index.js add-local-user --id lida --vault-path /vault
```

Обрати внимание: `--vault-path /vault` — это путь **внутри контейнера** (та самая папка из шага 3), а не путь на твоём компьютере. OpenAI-ключ тут не нужен: эмбеддинги считает GigaChat.

В ответ команда выдаст строчку вида:

```
  API Key: cv-XXXXXXXXXXXXXXXXXXXX
```

Скопируй этот ключ и сохрани — им ты будешь обращаться к поиску. Перезапускать ничего не надо: сервис подхватит нового пользователя сам и тут же начнёт индексировать папку.

---

## Шаг 8. Положить заметки и поискать

Брось пару файлов в папку `notes`:

```bash
cat > notes/otpusk.md <<'EOF'
# Заметка про отпуск
Лечу в Сочи в августе, бронь отеля на 10 ночей.
EOF
```

Подожди секунд десять — сервис проверяет папку раз в несколько секунд и индексирует новое. Теперь спроси у него (подставь свой ключ вместо `cv-...`):

```bash
curl -X POST http://localhost:3030/api/vault/search/semantic \
  -H "Authorization: Bearer cv-XXXXXXXXXXXXXXXXXXXX" \
  -H "Content-Type: application/json" \
  -d '{"query": "когда я еду в отпуск", "limit": 5}'
```

В ответ придут куски твоих заметок, отсортированные по смысловой близости к вопросу — даже если точных слов из запроса в тексте не было. В этом весь смысл: поиск по смыслу, а не по совпадению слов.

---

## Как пользоваться дальше

Всё просто: правишь файлы в папке `notes` как обычно — в любом редакторе. Добавила файл, изменила, удалила — сервис заметит это сам в течение нескольких секунд и обновит индекс. Спрашиваешь через тот же запрос из шага 8.

Можно фильтровать по тегам, проекту, типу файла — добавь в тело запроса блок `filters`. Полный список полей и других эндпоинтов (`/hybrid`, `/lexical`) лежит в Swagger: открой в браузере `http://localhost:3030/docs`.

---

## Управление

```bash
docker compose logs -f cognivault     # смотреть логи в реальном времени
docker compose restart cognivault     # перезапустить сервис
docker compose down                    # остановить всё (данные сохранятся в томах)
docker compose up -d --build cognivault qdrant   # снова поднять
```

Обновить CogniVault, когда выйдут новые правки:

```bash
git pull
docker compose up -d --build cognivault qdrant
```

## Если что-то пошло не так

**Поиск ничего не находит, хотя файлы в папке есть.**
Проверь логи (`docker compose logs cognivault`). Скорее всего файлы ещё не проиндексировались — подожди или убедись, что папка примонтирована (путь слева в `volumes` указывает на реальную папку с файлами).

**В логах ошибка про размер вектора или коллекцию Qdrant.**
Размерность не совпала. Поставь верное число в `EMBEDDING_DIMENSIONS`, потом пересоздай базу:

```bash
docker compose down
docker volume rm cognivault_qdrant_data
docker compose up -d --build cognivault qdrant
```

**В логах ошибка про сертификат или TLS.**
Сначала проверь, что пути в `GIGACHAT_CERT_PATH` и `GIGACHAT_KEY_PATH` указывают на реально лежащие в `certs` файлы. Если сервер GigaChat не признаётся доверенным — добавь файл CA через `GIGACHAT_CA_PATH`. Если CA пока нет, а проверить связь нужно срочно, временно раскомментируй `GIGACHAT_VERIFY_SSL=false` — это отключает проверку сервера. Для постоянной работы так оставлять не стоит, верни проверку, как получишь CA.

**Порт 3030 занят.**
Создай рядом файл `.env` со строкой `COGNIVAULT_PORT=8080` (или другой свободный порт) и подними заново. Адрес в запросах поменяется на этот порт.

**Сервис не стартует, в логах что-то про GIGACHAT_CERT_PATH или EMBEDDING_DIMENSIONS.**
Это значит, что при провайдере `gigachat` не хватает обязательной настройки. Проверь, что в `docker-compose.override.yml` заданы и сертификат, и ключ, и размерность.

---

Если застрянешь — пришли вывод `docker compose logs cognivault`, по нему почти всегда сразу видно, в чём дело.
