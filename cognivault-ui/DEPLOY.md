# Развёртывание CogniVault UI на рабочей машине

> **Это инструкция для установки на ОДНУ машину (режим `local`).**
> Централизованное развёртывание в кластере — отдельный, основной путь: он
> целиком описан в [`deploy/dropapp/README.md`](../deploy/dropapp/README.md).
> Если UI уже развёрнут в кластере, ставить ничего не нужно — откройте
> <http://cognivault-ui.apps.bcayrqks.k8s.delta.sbrf.ru>, введите свой токен
> `cv-…` и пользуйтесь; сертификаты GigaChat там общие, их держит под.

Пошаговая инструкция «нажми сюда, введи это» для установки CogniVault UI на **одну**
машину пользователя в закрытом контуре Сбера. Рассчитана на человека, который делает
это в первый раз. Идите строго по порядку.

CogniVault UI — это веб-интерфейс (FastAPI-сервер, локально — на
`127.0.0.1:8787`), который проксирует запросы к CogniVault и GigaChat и сам
собирает RAG-контекст. В режиме `local` конфиг, сертификаты и токены никогда не
покидают вашу машину.

---

## 1. Предпосылки (проверьте до начала)

**Python 3.10+.** Проверьте версию:

```bash
python3 --version
```

Должно быть `Python 3.10.x` или новее. Если команды нет или версия старая — поставьте
Python 3.10+ (через корпоративный установщик).

**Сетевой доступ из корпсети / VPN.** Должны открываться:

- SberOSC (зеркало pip): `https://sberosc.sigma.sbrf.ru`
- GigaChat: `https://gigachat-ift.sberdevices.delta.sbrf.ru`

Если GigaChat не открывается — вы не в том сетевом сегменте или не поднят VPN.

**Адрес бэкенда CogniVault.** Наружу из кластера выставлен **только UI**
(`cognivault-ui.apps.bcayrqks.k8s.delta.sbrf.ru`); сам REST API — Service типа
ClusterIP без Ingress, снаружи он недоступен. Значит, локальному UI нужен свой
источник данных, вариантов два:

- поднять бэкенд рядом на своей машине (`docker compose up -d cognivault qdrant`
  в корне репозитория) и указать `http://localhost:3030`;
- прокинуть порт в кластер: `oc port-forward svc/cognivault 3000:3000 -n
  ci05490208-oasis-cognivault` и указать `http://localhost:3000`.

Без одного из них локальный UI будет работать только как чат без RAG.

**Что нужно иметь на руках заранее:**

| Что | Откуда взять |
| --- | --- |
| Токен SberOSC | Портал SberOSC → **Профиль** → «скопировать токен» (<https://sberosc.sigma.sbrf.ru/dashboard/profile/>) |
| Токен CogniVault `cv-…` | Выдаёт админ командой `cognivault-ctl add-local-user` |
| Сертификаты mTLS GigaChat | Файлы `client_crt.crt` и `client_key.key` (выдаёт админ/владелец доступа) |

Без этих трёх вещей запуск не завершится — соберите их сначала.

## 2. Получить код

Скопируйте на машину папку `cognivault-ui/` целиком:

- либо `git clone <репозиторий>` и перейдите в `cognivault-ui/`,
- либо распакуйте zip с общего диска.

Дальше все команды выполняются **из папки `cognivault-ui/`**:

```bash
cd cognivault-ui
```

---

## 3. Развернуть окружение (один прогон)

Запустите bootstrap, передав токен SberOSC — так первый же прогон пройдёт до конца:

```bash
SBEROSC_TOKEN=<ваш-токен> python3 bootstrap.py
```

или эквивалентно:

```bash
python3 bootstrap.py --sberosc-token <ваш-токен>
```

> Если запустить `python3 bootstrap.py` без токена в терминале — скрипт **сам спросит**
> его в интерактивном режиме («Введите токен SberOSC …»); можно нажать Enter, чтобы
> пропустить. Токен нигде не печатается — в логах только вид `token:***@…`.

Что делает bootstrap:

1. создаёт каталоги `~/.cognivault-ui/{config.json, certs, history, tmp}`;
2. сохраняет токен и адрес зеркала в `~/.cognivault-ui/config.json` (`env.pip_token`,
   `env.pip_index_url`) **до** установки — поэтому pip сразу видит учётные данные;
3. создаёт виртуальное окружение `~/.cognivault-ui/venv`;
4. ставит зависимости (`fastapi`, `uvicorn`, `httpx`, `python-multipart`) через зеркало
   SberOSC.

Успешный финал выглядит так — скрипт печатает, как запускать сервер.

### Если pip падает с ошибкой

- **Свежая версия пакета «не находится».** Новые версии держатся в **карантине SberOSC
  ~3 дня**, прежде чем появятся в проксе. Подождите или попросите загрузить пакет.
- **404 на пакете, помеченном «Загружен в Nexus».** Переключите зеркало на Nexus —
  задайте другой index-url:

  ```bash
  python3 bootstrap.py --pip-index-url 'https://login:token@nexus-ci.sigma.sbrf.ru/repository/pypi-lib-ext/simple/'
  ```

Подробности про зеркала и `pip.conf` — в разделе «SberOSC PyPI mirror» файла `README.md`.

---

## 4. Положить сертификаты GigaChat

Скопируйте оба файла в каталог сертификатов:

```bash
cp client_crt.crt client_key.key ~/.cognivault-ui/certs/
```

Пути по умолчанию в конфиге уже указывают именно сюда:

- `gigachat.cert_path` → `~/.cognivault-ui/certs/client_crt.crt`
- `gigachat.key_path`  → `~/.cognivault-ui/certs/client_key.key`

Если имена файлов другие — либо переименуйте их к этим, либо позже поправьте пути в UI.

**Если приватный ключ зашифрован паролем** — задайте пароль в поле
`gigachat.key_passphrase` (через UI: Настройки → GigaChat, либо прямо в
`~/.cognivault-ui/config.json`).

---

## 5. Запустить

```bash
bash run.sh
```

Сервер поднимется на `127.0.0.1:8787`. Откройте в браузере:

**<http://localhost:8787>**

> Открывайте только через `http://localhost:8787`. Через `file://` SPA не работает —
> браузеру нужен этот сервер (same-origin), иначе `/api`-запросы и потоки не пройдут.

Чтобы остановить сервер — `Ctrl+C` в терминале.

---

## 6. Настроить в UI

В интерфейсе:

1. **Настройки → Подключение:** укажите адрес бэкенда CogniVault (см. шаг 1 —
   `http://localhost:3030` для локального стека или `http://localhost:3000` при
   port-forward) и вставьте токен CogniVault `cv-…`.
2. **Настройки → GigaChat и сертификаты:** проверьте пути к `client_crt.crt` /
   `client_key.key` и модель `GigaChat-3-Ultra-preview`. При зашифрованном ключе —
   впишите пароль.
3. Нажмите **Сохранить**.
4. Проверьте, что в шапке **три статус-пилюли зелёные** (соединение с CogniVault,
   сертификаты GigaChat, окружение). Если какая-то красная — см. раздел
   «Траблшутинг» ниже.

Остальные настройки трогать не обязательно — умолчания рабочие. Что там ещё
есть: параметры модели (`temperature`, `max_tokens`), ручки поиска и грейдера
(ширина ретрива, порог релевантности) и два редактируемых промпта. Полное
описание — в разделе «Настройки в UI» файла `README.md`.

---

## 7. Пользоваться

- **Чат:** обычный диалог с ассистентом.
- **RAG:** тумблер включает поиск по вашему вольту (заметкам) как контекст ответа.
  Под ответом появляются чипы источников с бейджем глубины (файл / раздел /
  фрагмент), а сам ответ ссылается на них как `[Источник N]`. Если ничего
  подходящего не нашлось, ассистент честно скажет об этом, а не придумает ответ.
- **Оценка ответа:** кнопки 👍/👎 под ответом — попадают в лог для последующего
  разбора качества.
- **Источник Confluence:** **Настройки → Источник Confluence** — основной способ
  наполнить вольт (см. раздел 11).
- **Загрузка заметок:** **Настройки → Загрузка файлов** — запасной путь: залейте
  zip с заметками, UI передаст его в CogniVault для индексации.
- **История:** слева список последних 10 чатов; клик открывает диалог.

## 8. Перенос на другую машину

CogniVault UI умеет упаковать всё окружение (конфиг + сертификаты + история +
`requirements`) в один архив:

1. На старой машине: **Настройки → Окружение → «Экспортировать окружение»** — скачается
   zip.
2. На новой машине: сначала пройдите bootstrap (шаг 3), затем **Настройки → Окружение →
   «Импортировать окружение»** и укажите путь к скачанному архиву.

После импорта проверьте зелёные статус-пилюли (шаг 6).

## 9. Массовая раскатка (кратко)

**Вариант А — раздать папку.** Разошлите папку `cognivault-ui/`; каждый пользователь
прогоняет `SBEROSC_TOKEN=<свой-токен> python3 bootstrap.py` со своим токеном SberOSC и
кладёт свои сертификаты. Просто и по-честному по токенам.

**Вариант Б — офлайн-набор wheels (для машин без токена/сети).** На машине **с** доступом
к зеркалу соберите колёса заранее:

```bash
pip download -r requirements.txt -d wheels
```

Раздайте папку `wheels/` вместе с кодом; на целевой машине поставьте без сети:

```bash
pip install --no-index --find-links wheels -r requirements.txt
```

**Вариант В — не раскатывать вообще.** Если UI уже развёрнут в кластере
(режим `server`), пользователю ничего ставить не нужно: он открывает
<http://cognivault-ui.apps.bcayrqks.k8s.delta.sbrf.ru>, вводит свой токен
`cv-…` — и получает собственный конфиг, собственную историю и собственный
источник Confluence (данные разложены по каталогам, ключ — хэш токена).
Сертификаты GigaChat при этом общие, их держит под. Процедура развёртывания —
[`deploy/dropapp/README.md`](../deploy/dropapp/README.md).

## 10. Траблшутинг

| Симптом | Причина | Что делать |
| --- | --- | --- |
| pip: `No matching distribution found` | Неверный index-url/токен SberOSC, либо пакет в 3-дневном карантине | Проверьте токен (шаг 3); подождите карантин или переключитесь на Nexus (`--pip-index-url …nexus-ci…`) |
| `GIGACHAT_DNS` — «Не удалось разрешить адрес GigaChat» | Нет VPN / не тот сетевой сегмент | Поднимите корпоративный VPN, убедитесь что открывается `gigachat-ift.sberdevices.delta.sbrf.ru` |
| `GIGACHAT_CERT_MISSING` — «Клиентский сертификат или ключ не найдены» | Нет файлов сертификатов по указанным путям | Положите `client_crt.crt` и `client_key.key` в `~/.cognivault-ui/certs/` (шаг 4) |
| `GIGACHAT_TLS` — ошибка TLS-соединения | Неверный/просроченный сертификат или неверный пароль ключа | Проверьте сертификаты и `gigachat.key_passphrase` |
| «Нет связи с CogniVault» | Неверный адрес или токен CogniVault; либо бэкенд просто не поднят | Бэкенд наружу из кластера не выставлен — поднимите его локально или сделайте `oc port-forward` (шаг 1), проверьте адрес и токен `cv-…` (шаг 6) |
| Порт `8787` занят | Уже запущен другой процесс на порту | Остановите старый процесс (`Ctrl+C` / найдите процесс на 8787) и запустите `bash run.sh` снова |

## 11. Источник Confluence

CogniVault UI умеет забирать дерево страниц Confluence в вольт: страницы
конвертируются в Markdown, вложения складываются рядом, а повторная
синхронизация обновляет только изменившееся.

### Как настроить

1. **Настройки → Источник Confluence.**
2. Заполните:
   - **Адрес** — базовый URL Confluence, например `https://confluence.sberbank.ru`.
   - **Аутентификация** — либо **логин/пароль** (HTTP Basic), либо **персональный
     токен (PAT)**. На SSO-контуре Basic часто отключён — тогда используйте PAT
     (Confluence → профиль → Personal Access Tokens).
   - **Ссылка на корень** — URL корневой страницы поддерева, которое надо забрать
     (подходят и `.../pages/viewpage.action?pageId=…`, и «красивые»
     `.../spaces/KEY/pages/…`, и `.../display/SPACE/Title`).
3. Нажмите **«Синхронизировать»**. Пойдёт поток прогресса: обход дерева, сравнение,
   запись страниц, вложения, удаления. Повторный запуск — инкрементальный.
4. **«Полная замена»** — сначала очищает вольт, затем заливает дерево заново
   (для «начать с чистого листа»).

### Что уточнить заранее

- **Включён ли HTTP Basic** на вашем Confluence. Если нет — берите **PAT** (UI сам
  подскажет ошибкой `Basic-аутентификация отключена — используйте PAT`).
- **Внутренний УЦ (CA).** Если Confluence за внутренним TLS, локальному UI нужен
  путь к PEM-бандлу; временно проверку можно снять (`CONFLUENCE_VERIFY_SSL=false`)
  — только как escape hatch, вернуть после появления бандла.
- **Примерный размер дерева** (число страниц/вложений) — чтобы прикинуть время
  первой полной синхронизации и объём вольта.

Кластерные тонкости (egress-ServiceEntry к `confluence.sberbank.ru:443`,
ConfigMap `sber-ca` с бандлом, `emptyDir` под `/data` и потеря манифеста при
перезапуске пода) относятся к серверному развёртыванию и описаны в
[`deploy/dropapp/README.md`](../deploy/dropapp/README.md) — на локальной машине
их нет: состояние лежит в `~/.cognivault-ui/` и переживает перезапуск.

> **«Очистить вольт»** в источнике Confluence заменяет ручную загрузку zip
> (Настройки → Загрузка файлов): дерево забирается и поддерживается автоматически,
> вручную заливать заметки больше не нужно.
