API Endpoints (all POST, require Bearer token):
- POST /api/vault/search/semantic  { query, limit?, filters? } -> { results: SearchResult[], total, limit, query_ms }
- POST /api/vault/search/lexical   { query, limit?, filters? } -> { results: SearchResult[], total, limit, query_ms }
- POST /api/vault/search/hybrid    { query, limit?, filters? } -> { results: SearchResult[], total, limit, query_ms }

SearchResult shape:
```typescript
{ text: string, path: string, title: string, section_path: string, score: number, tags: string[], project: string | null, status: string | null }
```

Environment variables:
- COGNIVAULT_API_KEY: Bearer token for auth
- BASE_URL: Server URL (default http://localhost:3000)

2. Create `test/eval/queries.json` with ~30-35 queries in three categories. Structure:
```json
{
  "queries": [
    { "id": "en-01", "category": "english", "query": "...", "relevant_paths": ["..."] },
    { "id": "ru-01", "category": "russian", "query": "...", "relevant_paths": ["..."] },
    { "id": "mixed-01", "category": "mixed", "query": "...", "relevant_paths": ["..."] }
  ]
}
```

Query content guidelines (per CONTEXT.md specifics):
- ~10 pure English: queries about Compass catalog UI, schema evolution, ingestion pipeline architecture, SLA ownership, deployment procedures, monitoring setup, API versioning, migration patterns, test coverage, data modeling
- ~10 pure Russian: queries about architecture decisions, project status, meeting notes, code review processes, onboarding docs, infrastructure setup, database design, security policies, team workflows, documentation standards
- ~10-15 mixed: queries mixing Russian context words with English technical terms (e.g., "Compass catalog ui filters", "как устроен ingestion metadata routes", "SLA ownership tabs", "schema evolution rules for GraphQL")
- Each query has 1-3 `relevant_paths` — use synthetic paths following Obsidian vault conventions (e.g., "Projects/Compass/catalog-filters.md", "Architecture/ingestion-pipeline.md")

3. Create `test/eval/eval.ts` — standalone CLI script using Node.js 22 native fetch:
   - Read env vars: `BASE_URL` (default http://localhost:3000), `COGNIVAULT_API_KEY` (required)
   - Load queries.json via `readFileSync` with `import.meta.url` path resolution
   - Define `recallAtK(retrieved: string[], relevant: string[], k: number): number` — standard IR formula (if relevant is empty, return 1.0; otherwise count hits in top-K / total relevant)
   - Define `search(endpoint: string, query: string, limit: number): Promise<string[]>` — POST to API, return result paths
   - Preamble check: Before running full eval, do a quick semantic search for a common term to verify server has indexed content. If results are empty, print warning and exit with code 2.
   - For each query, call all three endpoints (semantic, lexical, hybrid) with limit=10
   - Compute recall@10 for each query x endpoint combination
   - Aggregate by category (english, russian, mixed) and overall
   - Print tabular report:
     ```
     Category    | Semantic | Lexical | Hybrid
     ------------|----------|---------|-------
     english     | 0.85     | 0.70    | 0.90
     russian     | 0.75     | 0.65    | 0.80
     mixed       | 0.70     | 0.60    | 0.85
     ------------|----------|---------|-------
     overall     | 0.77     | 0.65    | 0.85

     Threshold: 0.7 — PASS/FAIL per category
     ```
   - Also print per-query details: query text, expected paths, actual retrieved paths (for debugging mismatches, per research pitfall #3)
   - Exit code 0 if all categories >= 0.7 threshold, exit code 1 if any category fails
   - Script is run with: `npx tsx test/eval/eval.ts`
   - Do NOT add this to pnpm test — it requires a running server with real vault data

Key constraints:
- Use Node.js 22 native fetch (no axios/node-fetch dependency)
- Metric is recall@10 per user decision
- Threshold is 0.7 per user decision
- Compare all three search types per user decision
- Script is in test/eval/ and NOT part of pnpm test per user decision
