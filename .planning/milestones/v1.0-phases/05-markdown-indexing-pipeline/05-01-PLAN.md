<feature>
  <name>Heading-Aware Markdown Chunker</name>
  <files>src/lib/chunker.ts, src/lib/__tests__/chunker.test.ts</files>
  <behavior>
    IDX-03: Heading boundary splitting
    - Input: "# H1\nParagraph 1\n## H2\nParagraph 2" with title "Test Note"
      Output: 2 chunks, first has sectionPath "Test Note", second has sectionPath "Test Note > H2"
    - Input: markdown with fenced code block containing "## fake heading"
      Output: code block stays intact in one chunk, NOT split at the fake heading
    - Input: markdown with GFM table
      Output: table stays whole, attached to its section's chunk
    - Input: note with no headings, just paragraphs
      Output: single section, split at paragraph boundaries if over 500 tokens

    IDX-03: Short section merging
    - Input: "## H2\nShort" (section <100 tokens)
      Output: merged into parent section's chunk

    IDX-03: Long section splitting
    - Input: heading section with >500 tokens of paragraphs
      Output: split at paragraph boundaries, each chunk <=500 tokens

    IDX-04: Section path metadata
    - Input: "# Title\n## Section\n### Sub"
      Output: chunks have sectionPath "Note Title > Section > Sub" (hierarchical)
    - Input: "## A\n...\n## B\n..."
      Output: B resets hierarchy (not nested under A)

    Obsidian syntax normalization:
    - "[[Page Name]]" in chunk text becomes "Page Name"
    - "[[Page|Alias]]" becomes "Alias"
    - "![[embed]]" is stripped
    - Callouts ("> [!note]") kept as text

    Frontmatter handling:
    - Frontmatter-only note (no body after frontmatter) returns empty array
    - Frontmatter content NOT in chunk text (gray-matter strips it before chunking)

    Chunk text format:
    - Each chunk text starts with "Note Title > Section Path\n\n{content}"
  </behavior>
  <implementation>
    Dependencies: remark-parse, unified, remark-gfm, js-tiktoken, @types/mdast (installed by Plan 05-02 to avoid pnpm add race in Wave 1 parallel execution)

    Use `unified().use(remarkParse).use(remarkGfm)` to parse markdown body (after gray-matter strips frontmatter) into mdast AST.

    Walk `root.children` to group nodes by heading boundaries:
    - Track heading stack (depth -> heading text) for section_path construction
    - When a heading node is encountered, finalize the previous section and start a new one
    - Heading depth determines hierarchy: H3 after H1 means stack is [H1, H3], H2 after H3 resets to [H1, H2]

    For each section, serialize nodes to text using a recursive nodeToText walker (extract text values from AST nodes, not remark-stringify).

    Apply Obsidian syntax normalization to the serialized text.

    Token counting with js-tiktoken `get_encoding('cl100k_base')`:
    - Initialize encoder ONCE at module level (expensive initialization)
    - Sections < MIN_TOKENS (~100) merge into parent
    - Sections > MAX_TOKENS (~500) split at paragraph boundaries (find paragraph node boundaries in the section's node list)

    Tables: if a section contains a table node, keep the table whole. If the table alone exceeds MAX_TOKENS, it becomes its own chunk.

    Code blocks: never split. If a code block is in a section, it stays with that section. Code blocks inside sections contribute to token count.

    Prepend "Title > Section Path\n\n" to each chunk's text.

    Export:
    - `chunkMarkdown(body: string, opts: ChunkOptions): MarkdownChunk[]`
    - `interface MarkdownChunk { text: string; sectionPath: string; chunkIndex: number; }`
    - `interface ChunkOptions { title: string; }`
    - `normalizeObsidianSyntax(text: string): string` (exported for testing)
    - Constants: `MIN_CHUNK_TOKENS = 100`, `MAX_CHUNK_TOKENS = 500`
  </implementation>
</feature>
