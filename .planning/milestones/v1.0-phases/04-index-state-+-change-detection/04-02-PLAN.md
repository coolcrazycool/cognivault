  <action>
    Create `src/lib/indexer.ts` with the VaultIndexer class:

    1. **Types and interface:**
       ```typescript
       export interface FileChangeEvent {
         path: string;
         type: 'created' | 'updated' | 'deleted' | 'moved';
         contentHash: string;
         oldPath?: string;
       }
       ```

    2. **VaultIndexer class** extends `EventEmitter` with typed event map `{ changes: [events: FileChangeEvent[]] }`:
       - Constructor takes: `{ db, vault, config, logger }` where db is the Drizzle instance, vault is VaultManager, config has POLL_INTERVAL_MS and STABILITY_DELAY_MS, logger is Fastify logger
       - Properties: `isIndexing: boolean` (public getter), `private running: boolean`, `private isPolling: boolean`, `private pollTimer: NodeJS.Timeout | null`, `private stabilityMap: Map<string, { hash: string; timer: NodeJS.Timeout }>`

    3. **hashFile(absolutePath: string): Promise<string>** — private method
       - Read file with `fs.readFile(absolutePath)` (returns Buffer, no encoding)
       - Return `crypto.createHash('sha256').update(buf).digest('hex')`

    4. **scanVault(): Promise<string[]>** — private method to get all .md file paths
       - Use `this.vault.listFiles({ recursive: true, ext: 'md' })` to get entries
       - Filter to type === 'file' only
       - Return array of relative paths (already POSIX from VaultManager)

    5. **start(): Promise<void>** — public method
       - Set isIndexing = true
       - Run initial scan (async, returns immediately to caller via void promise pattern)
       - After scan completes: set isIndexing = false, start poller
       - Use `void this.runInitialScan()` pattern so start() returns before scan finishes
       - Actually: start() should kick off the scan but NOT await it. Use `void this.runInitialScan().catch(err => this.logger.error(err))` so HTTP server can start.

    6. **runInitialScan(): Promise<void>** — private method
       - Get all .md files via scanVault()
       - Get all DB rows: `db.select().from(indexedFiles)`
       - Build Map of DB paths -> IndexedFile
       - Use p-limit(20) for concurrent file processing
       - For each .md file: stat + hashFile, build NewIndexedFile record
       - Compare filesystem vs DB:
         - Files on disk but not in DB -> 'created' events
         - Files in DB but not on disk -> 'deleted' events
         - Files in both but hash differs -> 'updated' events
         - Files in both with same hash -> no event
       - Batch upsert all current files into DB (use transaction for bulk insert)
       - Delete stale DB rows (files not on disk)
       - Emit events in chunks of 100 per 'changes' emission
       - Log progress every 500 files
       - Log summary: "Initial scan complete: N files indexed in Xs"
       - Set isIndexing = false
       - Call schedulePoll()

    7. **schedulePoll(): void** — private method
       - `this.pollTimer = setTimeout(() => { void this.runPollCycle(); }, this.config.POLL_INTERVAL_MS)`

    8. **runPollCycle(): Promise<void>** — private method
       - Guard: if isPolling, log warning and schedulePoll() and return
       - Set isPolling = true
       - try: call detectChanges()
       - catch: log error
       - finally: isPolling = false, if running then schedulePoll()

    9. **detectChanges(): Promise<void>** — private method
       - Scan vault for current .md files + stat + hash each
       - Query all DB rows
       - Determine candidates:
         - deletedPaths: in DB, not on filesystem
         - createdPaths: on filesystem, not in DB
         - existingPaths: in both
       - For created files: run stability check (checkStability)
         - If stable: classify as truly new
       - For existing files with changed hash: run stability check
         - If stable: classify as updated
       - **Move detection:** For each stable created file, check if its hash matches any deleted file's hash (query deletedPaths). If match: emit 'moved' with oldPath. Remove from both created and deleted lists.
       - For remaining deleted: emit 'deleted' events
       - For remaining created: emit 'created' events
       - For updated: emit 'updated' events
       - Update DB: upsert created/updated/moved, delete removed
       - Emit all events as single 'changes' batch (unless empty)
       - Log summary at info level if changes > 0, debug level for individual files

    10. **checkStability(absolutePath: string, firstHash: string): Promise<string | null>** — private method
        - Wait STABILITY_DELAY_MS via `new Promise(resolve => setTimeout(resolve, delay))`
        - Re-hash the file
        - If second hash === first hash, return the hash (stable)
        - If different or file gone, return null (unstable, skip this cycle)

    11. **stop(): void** — public method
        - Set running = false
        - Clear pollTimer if set
        - Clear all stability timers

    - Listen to 'changes' events and collect them for assertions
