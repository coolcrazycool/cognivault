<task type="auto" tdd="true">
  <name>Task 1: Rewrite indexer plugin as per-user indexer manager</name>
  <files>
    src/plugins/indexer.ts
    src/plugins/__tests__/indexer.test.ts
  </files>
  <behavior>
    - At plugin init, creates VaultIndexer for each existing registry user (via onReady hook)
    - fastify.indexers Map is decorated on FastifyInstance
    - fastify.indexers.get(userId) returns user's VaultIndexer
    - On user-added event, creates new VaultIndexer for user and starts it (if vault path exists)
    - On user-removed event, stops VaultIndexer, clears its PQueue, removes user metrics, deletes from Map
    - If user's vaultPath doesn't exist on disk, logs warning and skips indexer creation (no crash)
    - On server close, stops all indexers and clears Map
    - Each VaultIndexer gets the user's DB via fastify.getUserDbById(userId)
    - Each VaultIndexer gets a new VaultManager created with user's vaultPath
    - Each user gets their own PQueue with concurrency 3 and timeout 120s
    - Indexer events ('changes') are forwarded to pipeline processing with userId context
  </behavior>
  <action>
    **Rewrite src/plugins/indexer.ts:**

    1. Remove old single-indexer code entirely
    2. Create new structure:
       - `Map<string, { indexer: VaultIndexer; queue: PQueue; vault: VaultManager }>` to hold per-user indexers, queues, and vault managers
       - Module augmentation: `fastify.indexers: Map<string, { indexer: VaultIndexer; queue: PQueue; vault: VaultManager }>`
    3. Import PQueue, VaultManager (from '../lib/vault.js'), VaultIndexer
    4. Create helper `createUserIndexer(fastify, userId, vaultPath)`:
       - Validate vaultPath exists on disk (fs.access). If not, log warning and return null
       - Create VaultManager with user's vaultPath
       - Create VaultIndexer with: db from fastify.getUserDbById(userId), vault from new VaultManager, config from fastify config (POLL_INTERVAL_MS, STABILITY_DELAY_MS), logger as child logger with userId
       - Create PQueue with concurrency 3, timeout 120_000
       - Wire indexer 'changes' event to pipeline processing (see pipeline task for the handler interface)
       - The indexer 'changes' listener should call `fastify.processFileChanges(userId, events)` (decorated by pipeline plugin)
       - Store { indexer, queue, vault } in Map, return the entry
    5. At plugin init: decorate fastify.indexers with the Map
    6. In onReady hook: create indexers for all existing registry users and start them
    7. Registry event listeners:
       - user-added: createUserIndexer and start it
       - user-removed: stop indexer, queue.clear(), await queue.onIdle(), call `fastify.metrics.removeUserMetrics(userId)` to clean up stale metric labels (per locked decision), delete from Map
    8. onClose hook: stop all indexers, clear all queues, clear Map
    9. fp() dependencies: ['db', 'registry', 'qdrant', 'embedder', 'metrics', 'pipeline']
       - Indexer depends on pipeline because it calls fastify.processFileChanges
       - Start indexers in onReady (after all plugins registered)

    **Rewrite src/plugins/__tests__/indexer.test.ts:**
    - Remove describe.skip, write new tests
    - Mock VaultIndexer, VaultManager, PQueue, fs.access
    - Test: creates indexers for existing users on ready
    - Test: skips indexer if vault path doesn't exist
    - Test: user-added creates and starts new indexer
    - Test: user-removed stops indexer, clears queue, and calls removeUserMetrics
    - Test: onClose stops all indexers
    - Test: fastify.indexers.get(userId) returns correct entry
  </action>

  </verify>

    - VaultIndexer created per user with their own DB, VaultManager, PQueue
    - Vault path validated before indexer creation

    - All metrics pass { user_id: userId } with every .inc() / .startTimer()
    - DB updates (indexed_files) use per-user DB from getUserDbById
    - VaultManager readContent uses per-user vault (via TenantQdrantClient paths stay relative)
    - processDeleted uses tenant Qdrant for vector deletion
    - processMoved uses tenant Qdrant for payload update
  </behavior>
  <action>
    **Rewrite src/plugins/pipeline.ts:**

    1. Remove @ts-nocheck at the top
    2. Remove old `declare module 'fastify'` for pipelineQueue (no longer a single global queue)
    3. Add new module augmentation: `fastify.processFileChanges: (userId: string, events: FileChangeEvent[]) => void`
    4. Define a `UserFileChangeEvent` extending FileChangeEvent with userId field
    5. Keep chunkId function as-is (already takes userId, filePath, chunkIndex)
    6. Refactor embedAndUpsert:
       - Takes (fastify, userId, event, chunks, extraPayload)
       - Gets embedder via `fastify.getUserEmbedder(userId)`
       - Gets tenant Qdrant via `fastify.createTenantQdrant(userId)` (uses .upsert/.delete on tenant client -- NOT collection name since TenantQdrantClient wraps that)
       - Gets DB via `fastify.getUserDbById(userId)` for indexed_files update
       - Passes { user_id: userId } to all metric calls
       - Uses chunkId(userId, filePath, chunkIndex) for point IDs
       - Note: TenantQdrantClient methods (upsert, delete, search, setPayload) take data directly, NOT collection name. Check TenantQdrantClient interface.
    7. Refactor processMarkdown, processImage, processCreatedOrUpdated, processDeleted, processMoved:
       - All receive (fastify, userId, event) instead of (fastify, event)
       - All use tenant Qdrant and per-user DB
       - processImage: reads markdown files from per-user DB
       - For vault file reading: access per-user VaultManager from `fastify.indexers.get(userId)!.vault`. The indexer Map entry stores `{ indexer, queue, vault: VaultManager }` (created in Task 1). Pipeline accesses it directly -- no need to create a separate VaultManager or look up registry.
    8. processFileChanges function:
       - Decorated on fastify
       - Takes (userId, events) -- called by indexer's changes listener
       - For each event, adds to the USER's PQueue (from fastify.indexers.get(userId).queue)
       - Updates indexQueueDepth gauge with { user_id: userId } after each add
       - PQueue 'next' and 'idle' events update gauge per user
    9. pipelinePlugin:
       - Just decorates processFileChanges and sets up nothing else (no global queue, no global indexer listener)
       - fp() dependencies: ['qdrant', 'embedder', 'db', 'metrics', 'registry']
       - Note: pipeline does NOT depend on indexer. Indexer depends on pipeline. The processFileChanges is a function that indexer calls.
    10. Queue depth tracking: Since PQueue events don't carry userId, the gauge update must happen in the task wrapper. After queue.add(), set gauge. In the finally block of each task, update gauge.

    **IMPORTANT corrections for TenantQdrantClient usage:**
    - TenantQdrantClient methods do NOT take collection name. They wrap the raw client and auto-inject collection name and user_id filter.
    - Confirm by checking src/lib/tenant-qdrant-client.ts interface: methods like upsert(points), delete(filter), search(params), setPayload(params).
