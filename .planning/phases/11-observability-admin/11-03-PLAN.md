  <name>Task 2: Manual spans in search/context routes with trace ID log injection</name>
  <files>src/features/search/routes.ts, src/features/context/routes.ts</files>
  <action>
    1. Modify `src/features/search/routes.ts`:
       - Import `trace, SpanStatusCode` from `@opentelemetry/api`
       - Create module-level tracer: `const tracer = trace.getTracer('cognivault-search')`
       - Wrap each search handler's core logic in `tracer.startActiveSpan()`:
         - /semantic: span name `'search.semantic'`, set `search.results_count` attribute
         - /hybrid: span name `'search.hybrid'`, set `search.results_count` attribute
         - /lexical: span name `'search.lexical'`, set `search.results_count` attribute
       - In each span: try/catch with `span.recordException(err)` + `span.setStatus({ code: SpanStatusCode.ERROR })` on error, `span.end()` in finally
       - Add trace ID to request log: at start of each handler, check `trace.getActiveSpan()`, if present, call `request.log = request.log.child({ traceId: span.spanContext().traceId })` — this injects traceId into all subsequent log entries for this request
       - Note: When OTel is not initialized, `trace.getTracer()` returns a no-op tracer, `startActiveSpan` just calls the callback, and `getActiveSpan()` returns undefined. Zero overhead by design.

    2. Modify `src/features/context/routes.ts`:
       - Import `trace, SpanStatusCode` from `@opentelemetry/api`
       - Create tracer: `const tracer = trace.getTracer('cognivault-context')`
       - Wrap handler in `tracer.startActiveSpan('context.assemble', ...)` with same pattern
       - Set attributes: `context.chunks_count`, `context.token_budget`
       - Add trace ID log injection same as search routes
  </action>
