1. In `docker-compose.yml`, update the cognivault service:
   - Change `COGNIVAULT_DATA_DIR=/tmp/cognivault-data` to `COGNIVAULT_DATA_DIR=/data`
   - Add `cognivault_data:/data` to the volumes list (after the vault bind mount)
   - Add `cognivault_data:` to the top-level `volumes:` block (alongside qdrant_data, prometheus_data, grafana_data)

The result should look like:
```yaml
services:
  cognivault:
    environment:
      - COGNIVAULT_DATA_DIR=/data
    volumes:
      - ${VAULT_PATH:-./__vault}:/vault:ro
      - cognivault_data:/data

volumes:
  qdrant_data:
  prometheus_data:
  grafana_data:
  cognivault_data:
```

2. In `monitoring/prometheus/rules/cognivault.yml`, update the HighErrorRate alert:
   - Change `for: 5m` to `for: 30m`
   - Update the description annotation to: "CogniVault is up but no search requests have been processed in the last 30 minutes. Check if the service is receiving traffic."

This prevents false-positive alerts during normal development idle periods or off-hours while still catching genuinely stalled search processing after 30 minutes.
