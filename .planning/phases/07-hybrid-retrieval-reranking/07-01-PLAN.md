1. In schemas.ts, add `hybridSearchSchema` — identical structure to `semanticSearchSchema` and `lexicalSearchSchema` (same body/response schemas). Export it as a named export.

2. In service.ts, add `hybrid()` public method to SearchService:
   - Signature: `async hybrid(query: string, limit: number, filters: SearchFilters): Promise<SearchResult[]>`
   - Call `this.semantic(query, limit * 2, filters)` and `this.lexical(query, limit * 2, filters)` via `Promise.all` (parallel, not sequential)
   - Apply RRF fusion with hardcoded `K = 60`:
     - Create `Map<string, { result: SearchResult; score: number }>` keyed by `result.path`
     - For each result list, accumulate `1 / (rank + K)` where rank is 1-based index
     - If same path appears in both lists, add scores together
   - Sort by fused score descending, take top `limit`
   - Clamp scores with `Math.min(1, Math.max(0, score))` — do NOT use relative normalization (raw RRF scores already in [0,1], per research recommendation)
   - Return the sliced, score-clamped results

3. In routes.ts, add POST `/hybrid` route following the exact same pattern as `/semantic` and `/lexical`:
   - Import `hybridSearchSchema` from schemas
   - Create `SearchService` per-request (stateless, same pattern)
   - Call `searchService.hybrid(query, limit, filters)`
   - Return `{ results, total: results.length, limit, query_ms: Date.now() - start }`

4. In __tests__/routes.test.ts, add `describe('POST /api/vault/search/hybrid')` block with tests for all behaviors listed above. Use the existing mock infrastructure (mockQdrantSearch, mockQdrantScroll, mockEmbed). For the dedup test, configure mocks so both semantic and lexical return a result with the same path.
