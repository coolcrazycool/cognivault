In `src/plugins/sync.ts`, find the `user-removed` event handler (where sync processes are stopped for a removed user). After stopping the sync process, add cleanup of sync metric labels:

```typescript
syncRunning.remove({ user_id: user.userId });
syncFailures.remove({ user_id: user.userId });
```

This ensures that when a user is removed from the registry, their sync metrics don't linger in Prometheus with stale values.

The `syncRunning` and `syncFailures` variables are already defined at plugin scope, so they're accessible from the event handler. Verify that the `user-removed` handler already calls `syncRunning.set({ user_id: ... }, 0)` — the `.remove()` call should come AFTER that to fully clean up the label combination.

Also verify in the existing sync.ts code: when a sync process is stopped for a removed user, `syncRunning.set({ user_id }, 0)` is called. The `.remove()` call replaces this behavior — no need to set to 0 first if we're removing the label entirely. Change the `.set(0)` to `.remove()` for the user-removed path (not for temporary stops/restarts).
