Test cases (per user decision — search + notes CRUD):

**Test 1: "User B cannot find User A notes via search"**
- Use User A's API key to trigger indexing of their vault (via admin reindex endpoint or by waiting for indexer to pick up files).
- Use User B's API key to search for content that exists in User A's vault.
- Assert: response 200, results array has length 0.

**Test 2: "User B gets 404 for User A note path"**
- User A has a note at a known path.
- User B requests GET /api/vault/notes/{that-path} with User B's API key.
- Assert: response 404.

**Test 3: "User A can find their own notes via search"**
- User A searches for their own content.
- Assert: response 200, results array has length > 0.

**Test 4: "User A can read their own note"**
- User A requests GET /api/vault/notes/{their-note-path} with User A's API key.
- Assert: response 200 with note content.

Cleanup in afterAll:
- `await app.close()`
- Remove temp directories and users.json

Important notes:
- This test requires a real Qdrant instance running (not mocked). Skip with `describe.skipIf(!process.env.QDRANT_URL)` or similar if Qdrant is unavailable.
- The test must wait for indexing to complete before searching. Use the admin reindex endpoint or poll the health/readiness endpoint for indexing status.
- Use unique user IDs with UUID-like values to avoid collision with any existing Qdrant data.

  <action>
Create `test/docker-smoke.sh` — a lightweight shell script that verifies the Docker image boots and becomes healthy.

```bash
#!/usr/bin/env bash
set -euo pipefail

IMAGE="cognivault:smoke-test"
CONTAINER="cognivault-smoke-$$"

cleanup() {
  docker rm -f "$CONTAINER" 2>/dev/null || true
}
trap cleanup EXIT

echo "Building image..."
docker build -t "$IMAGE" .

echo "Starting container..."
docker run -d --name "$CONTAINER" \
  -e QDRANT_URL=http://host.docker.internal:6333 \
  -e LOG_LEVEL=warn \
  -e COGNIVAULT_DATA_DIR=/data \
  -e EMBEDDING_MODEL=text-embedding-3-small \
  -p 0:3000 \
  "$IMAGE"

# Wait for container to be healthy (up to 60s)
echo "Waiting for healthcheck..."
for i in $(seq 1 12); do
  STATUS=$(docker inspect --format='{{.State.Health.Status}}' "$CONTAINER" 2>/dev/null || echo "starting")
  if [ "$STATUS" = "healthy" ]; then
    echo "Container healthy after $((i * 5))s"

    # Get the mapped port
    PORT=$(docker port "$CONTAINER" 3000/tcp | head -1 | cut -d: -f2)

    # Hit /health endpoint directly
    HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" "http://localhost:${PORT}/health" || echo "000")
    if [ "$HTTP_CODE" = "200" ]; then
      echo "Health endpoint returned 200"
      echo "SMOKE TEST PASSED"
      exit 0
    else
      echo "Health endpoint returned $HTTP_CODE" >&2
      docker logs "$CONTAINER" >&2
      exit 1
    fi
  fi
  sleep 5
done

echo "Container did not become healthy within 60s" >&2
docker logs "$CONTAINER" >&2
exit 1
```

Make the script executable: `chmod +x test/docker-smoke.sh`

The script:
1. Builds the Docker image from the project root Dockerfile
2. Starts a container with v2.0 env vars (no VAULT_PATH, no API keys)
3. Waits up to 60s for Docker healthcheck to pass
4. Curls /health endpoint to verify 200 response
5. Cleans up the container on exit (trap)
6. Uses PID in container name to avoid collisions with parallel runs

Note: The smoke test does NOT require Qdrant to be available — the container should start healthy with zero users even if Qdrant is unreachable (healthcheck hits /health which skips auth and returns basic status). If healthcheck fails because Qdrant is required for startup, this signals a config issue that needs fixing.
