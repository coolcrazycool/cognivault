**schemas.ts** — Create TypeBox schemas for search endpoints:

1. `SearchFiltersSchema`: Optional object with `tags` (string array), `project` (string), `status` (string), `folder` (string) — all optional.

2. `SearchRequestBodySchema`: Object with `query` (string, minLength: 1), `limit` (optional integer, min 1, max 50, default 10), `filters` (optional SearchFiltersSchema).

3. `SearchResultSchema`: Object with `text` (string), `path` (string), `title` (string), `section_path` (string), `score` (number, min 0, max 1), `tags` (string array), `project` (string | null), `status` (string | null).

4. `SearchResponseSchema`: Object with `results` (array of SearchResultSchema), `total` (integer), `limit` (integer), `query_ms` (integer).

5. Route schema objects `semanticSearchSchema` and `lexicalSearchSchema` — both use `SearchRequestBodySchema` as body, `SearchResponseSchema` as 200 response, `ErrorResponseSchema` (from vault schemas) as 400/500.

Export all schemas and their Static types.

**service.ts** — Create SearchService class:

Constructor takes `qdrant: QdrantClient` and `embedder: EmbeddingProvider`.

`async semantic(query: string, limit: number, filters: SearchFilters): Promise<SearchResult[]>`:
1. Embed query: `const [embedding] = await this.embedder.embed([query])`
2. Call `this.qdrant.search(COLLECTION_NAME, { vector: embedding as number[], limit, with_payload: true, filter: this.buildFilter(filters) })`
3. Map hits to SearchResult using `toSearchResult(hit, normalizeScore(hit.score))`

`async lexical(query: string, limit: number, filters: SearchFilters): Promise<SearchResult[]>`:
1. Build must conditions from filters using `buildMustConditions()`
2. Call `this.qdrant.scroll(COLLECTION_NAME, { filter: { must: mustConditions.length > 0 ? mustConditions : undefined, should: [ { key: 'text', match: { text: query } }, { key: 'title', match: { text: query } }, { key: 'section_path', match: { text: query } } ] }, limit, with_payload: true })`
3. IMPORTANT: scroll() returns `result.points` (not `result.result`) — see Pitfall 1 in RESEARCH.md
4. Lexical results have NO score field — assign 1.0 for all (Pitfall 2)
5. Filter out points without `text` payload (legacy chunks pre-reindex)
6. Map to SearchResult

**Private helper methods on SearchService:**

`buildFilter(filters)`: Returns a Qdrant Filter object or undefined if no filters.

`buildMustConditions(filters)`: Returns Condition array:
- `tags` with length > 0: `{ key: 'tags', match: { any: filters.tags } }` (MatchAny for OR logic — Pitfall 5)
- `project`: `{ key: 'project', match: { value: filters.project } }`
- `status`: `{ key: 'status', match: { value: filters.status } }`
- `folder`: Do NOT use Qdrant filter (path is keyword-indexed, not text-indexed — Pitfall 3). Instead, set a `_folderPrefix` flag and post-filter results using `String.prototype.startsWith()` in the result mapping step. Add a TODO comment: "At scale, add a text index on path field to push filtering to Qdrant."

`normalizeScore(raw: number): number`: `Math.min(1, Math.max(0, raw))` — clamp to [0, 1] (no min-max normalization per batch — Anti-Pattern from RESEARCH.md).

`toSearchResult(point, score)`: Map payload fields to SearchResult shape. Handle null/undefined gracefully for optional fields.
